## 二、报告遗漏的问题（本次核验新增发现）

### 2.1 三套主色令牌源不同步（最严重，已登记 C-9）

```
亮色运行时：variables.css:4   --color-primary: #2b5fd7   （CSS 变量）
编译期固化：common-forms.scss:11  $primary-color: #2b5fd7  （SCSS 变量，独立维护）
暗色 EP 侧：dark.css:10       --el-color-primary: #4a90e2 （Element Plus 变量，色相不同！）
```

- 同一"主色"概念三处声明；暗色下 EP 组件（#4a90e2）与 SCSS 固化亮色（#2b5fd7）并排呈现两种蓝。
- 即使全部改为 `var()`，三源不同步问题仍在——**收敛令牌源是暗色修复的前置条件**。
- 令牌命名双轨：`variables.css` 用 `--color-*`，`dark.css` 补 `--el-color-*`，只搜一套前缀会漏另一套。

### 2.2 `!important` 特异性战争：63 处（已登记 C-10）

- Top 分布：`WasteAssetDetails` / `UnregisteredAssetDetails` / `OutAssetDetails` / `OperationLogDetails.scss` / `HardDiskSNDetails` 各 8 处。
- 场景：各详情页用 `!important` 对抗公共组件（`CommonList`）内部样式。任何改 `CommonList` 样式的行为都会被这 63 处静默拦截或引发连锁回归。
- 报告只提了 `:deep()` 的 DRY 重复，未提覆盖冲突本身。

### 2.3 z-index 并列 1000 ×2，无层级令牌（已登记 D-6）

- 全仓 `z-index` 仅 3 个文件使用，但两个独立浮层同写 `z-index: 1000`；EP 弹窗默认 ~2000+。
- 当前无实际遮盖缺陷，但并列 1000 的浮层同屏时遮盖关系取决于 DOM 顺序而非设计意图。
- 关联：详情页"子路由激活遮罩"（`isChildRouteActive` + route watcher，15 个 `handleExportExcel` 文件同构批次）的遮罩 z-index/透明度为各页手写，报告完全未触及。

### 2.4 其他补充

- **`@media` 并非全无**：全仓 18 个文件含 `@media`，报告"响应式缺失"应精确表述为"关键布局组件（MainView/AsideMenu/LogIn）缺失"，而非全仓缺失。
- **ECharts 暗色适配缺一步**：即使改用 `getComputedStyle` 读 CSS 变量，也只在初始化时生效；`.dark` 切换时须**重建图表实例**，报告的 useChartTheme 方案未提这步。

## 三、修复路线（核验后修订版）

### Phase 1 — 暗色模式（前置：令牌源收敛）

1. **统一三源**（C-9）：`common-forms.scss` SCSS 变量删除/改为引用 CSS 变量；`dark.css` 的 `--el-color-primary` 与亮色对齐（或声明暗色专用色阶——需产品决策）。
2. 组件替换：AsideMenu / LogIn / Dashboard 的 SCSS 变量引用 → `var(--color-*)`。
3. ECharts：`useChartTheme` composable 读 `getComputedStyle` + **`.dark` 切换时重建实例**。

### Phase 2 — 响应式 + 无障碍

1. `LogIn.vue` 卡片 `width: 90%; max-width: 480px`。
2. `MainView.vue` 移动端侧边栏 overlay/drawer。
3. `DarkModeToggle`/折叠按钮 `role="button"` + `tabindex="0"` + 键盘事件；登录表单 `autocomplete`。

### Phase 3 — DRY + 覆盖战争

1. 2 个批导入组件统一 `BatchImportGuideCard`。
2. 提取共享 `handleExportTemplate` 工具。
3. `:deep(.el-table)` 收敛为共享 SCSS mixin（C-10 专项，含 63 处 `!important` 消解）。
4. 路由直接 API 调用改经 Pinia Store（~21 组件/视图）——**架构分层问题，单独评估，不搭 DRY 顺车**。
